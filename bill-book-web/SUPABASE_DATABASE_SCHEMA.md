# BillBook Supabase Database Schema

**Project:** BillBook billing, inventory, accounting, GST and reporting web app

**Target:** Supabase PostgreSQL
**Prepared:** 24 September 2026

## 1. Purpose and Conventions

This document converts the current frontend sample data and page workflows into a production-ready relational model. The current application stores sample objects in localStorage; these tables are the backend contract to implement in Supabase.

- Every business table is scoped by `organization_id` for tenant isolation.
- Primary keys use `bigint generated by default as identity`, except Supabase Auth users and organizations, which use `uuid`.
- Money uses `numeric(14,2)`; quantities use `numeric(14,3)`; tax percentages use `numeric(5,2)`.
- Use `date` for business dates and `timestamptz` for audit timestamps.
- Use Supabase `auth.users` for passwords. Never store passwords in application tables.
- Add RLS policies so users can only access rows for their organization.
- Names copied onto document lines are intentional snapshots, so old invoices remain readable after a product is renamed.

## 3. Organization and Access Tables

### `organizations`

| Column | Type | Rules / meaning |
|---|---|---|
| `id` | `uuid` | PK; default `gen_random_uuid()` |
| `company_name` | `text` | Required |
| `address` | `text` | Nullable |
| `gstin` | `text` | Nullable; unique per organization if applicable |
| `currency` | `text` | Default `INR` |
| `timezone` | `text` | Default `Asia/Kolkata` |
| `invoice_prefix` | `text` | Default `INV` |
| `po_prefix` | `text` | Default `PO` |
| `fiscal_year_start_month` | `smallint` | 1-12; default 4 |
| `created_at`, `updated_at` | `timestamptz` | Required; default `now()` |

### `stores`

`id bigint PK`, `organization_id uuid FK organizations`, `name text NOT NULL`, `address text`, `phone text`, `active boolean DEFAULT true`, `created_at timestamptz`, `updated_at timestamptz`.

### `roles`

`id bigint PK`, `organization_id uuid FK`, `name text NOT NULL`, `permissions jsonb NOT NULL DEFAULT '{}'`, `created_at timestamptz`, `updated_at timestamptz`.

`permissions` contains module actions such as `view`, `create`, `edit`, `delete`, and `export`.

### `modules`

`id bigint PK`, `key text UNIQUE NOT NULL`, `label text NOT NULL`, `created_at timestamptz`.

### `role_module_access`

`role_id bigint FK roles`, `module_id bigint FK modules`, `can_access boolean DEFAULT false`. Composite primary key: `(role_id, module_id)`.

### `staff_users`

`id uuid PK FK auth.users`, `organization_id uuid FK`, `name text NOT NULL`, `email text NOT NULL`, `role_id bigint FK roles`, `store_id bigint FK stores`, `department text`, `status user_status DEFAULT 'Active'`, `created_at timestamptz`, `updated_at timestamptz`.

### `activity_logs`

`id bigint PK`, `organization_id uuid FK`, `user_id uuid FK staff_users`, `action text NOT NULL`, `entity_type text`, `entity_id bigint`, `timestamp timestamptz DEFAULT now()`.

## 4. Product Catalog Tables

### `categories`

`id bigint PK`, `organization_id uuid FK`, `name text NOT NULL`, `active boolean DEFAULT true`, `created_at timestamptz`, `updated_at timestamptz`. Do not store `product_count`; calculate it.

### `brands`

`id bigint PK`, `organization_id uuid FK`, `name text NOT NULL`, `active boolean DEFAULT true`, `created_at timestamptz`, `updated_at timestamptz`.

### `units`

`id bigint PK`, `organization_id uuid FK`, `name text NOT NULL`, `short text NOT NULL`, `created_at timestamptz`, `updated_at timestamptz`.

### `manufacturers`

`id bigint PK`, `organization_id uuid FK`, `name text NOT NULL`, `country text`, `created_at timestamptz`, `updated_at timestamptz`.

### `products`

| Column | Type | Rules / meaning |
|---|---|---|
| `id` | `bigint` | PK identity |
| `organization_id` | `uuid` | FK `organizations.id`, required |
| `name` | `text` | Required |
| `type` | `product_type` | `Simple` or `Variable` |
| `sku`, `barcode`, `hsn` | `text` | SKU/barcode/HSN; SKU unique per organization |
| `category_id`, `brand_id`, `unit_id`, `manufacturer_id` | `bigint` | Nullable FKs to catalog tables |
| `cost_price`, `sell_price` | `numeric(14,2)` | Required prices |
| `tax_rate` | `numeric(5,2)` | Percentage, 0-100 |
| `alert_qty`, `min_qty`, `qty_step` | `numeric(14,3)` | Stock thresholds and quantity increment |
| `description` | `text` | Nullable |
| `active` | `boolean` | Default true |
| `created_at`, `updated_at` | `timestamptz` | Audit timestamps |

Do not use a single `stock` column on products as authoritative inventory. Use `inventory_balances` and `inventory_movements`.

## 5. Contacts

### `contacts`

`id bigint PK`, `organization_id uuid FK`, `name text NOT NULL`, `type contact_type`, `phone text`, `email text`, `gstin text`, `address text`, `opening_balance numeric(14,2) DEFAULT 0`, `active boolean DEFAULT true`, `created_at timestamptz`, `updated_at timestamptz`.

`contact_type` values: `Customer`, `Supplier`, `Both`. Calculate live balance from invoices, purchases, returns and payments instead of storing a mutable balance.

## 6. Sales Tables

### `sales_orders`

`id bigint PK`, `organization_id uuid FK`, `store_id bigint FK`, `customer_id bigint FK contacts`, `reference text NOT NULL`, `order_date date NOT NULL`, `subtotal numeric(14,2)`, `tax_amount numeric(14,2)`, `discount_amount numeric(14,2)`, `total numeric(14,2)`, `status sales_order_status`, `created_by uuid FK staff_users`, `created_at timestamptz`, `updated_at timestamptz`.

### `sales_order_items`

`id bigint PK`, `sales_order_id bigint FK`, `product_id bigint FK`, `product_name text NOT NULL` (snapshot), `quantity numeric(14,3)`, `unit_price numeric(14,2)`, `tax_rate numeric(5,2)`, `line_subtotal numeric(14,2)`, `tax_amount numeric(14,2)`, `line_total numeric(14,2)`.

### `invoices`

`id bigint PK`, `organization_id uuid FK`, `store_id bigint FK`, `customer_id bigint FK contacts`, `sales_order_id bigint FK nullable`, `reference text NOT NULL`, `invoice_date date NOT NULL`, `subtotal numeric(14,2)`, `tax_amount numeric(14,2)`, `discount_amount numeric(14,2)`, `total numeric(14,2)`, `paid_amount numeric(14,2) DEFAULT 0`, `due_amount numeric(14,2)`, `status invoice_status`, `created_by uuid FK staff_users`, `created_at timestamptz`, `updated_at timestamptz`.

### `invoice_items`

`id bigint PK`, `invoice_id bigint FK`, `product_id bigint FK`, `product_name text NOT NULL` (snapshot), `quantity numeric(14,3)`, `unit_price numeric(14,2)`, `tax_rate numeric(5,2)`, `hsn text` (snapshot), `line_subtotal numeric(14,2)`, `tax_amount numeric(14,2)`, `line_total numeric(14,2)`.

### `payments`

`id bigint PK`, `organization_id uuid FK`, `reference text`, `contact_id bigint FK contacts`, `invoice_id bigint FK invoices nullable`, `purchase_id bigint FK purchases nullable`, `bank_account_id bigint FK bank_accounts nullable`, `payment_date date NOT NULL`, `direction payment_direction`, `mode payment_mode`, `amount numeric(14,2)`, `notes text`, `created_by uuid FK staff_users`, `created_at timestamptz`.

Use `direction = Received` for customer receipts and `Paid` for supplier/expense payments. `mode` values: `Cash`, `Card`, `UPI`, `Bank`.

### `sale_returns` and `sale_return_items`

`sale_returns`: `id bigint PK`, `organization_id uuid FK`, `reference text`, `original_invoice_id bigint FK invoices`, `customer_id bigint FK contacts`, `return_date date`, `amount numeric(14,2)`, `reason text`, `status return_status`, `created_by uuid FK staff_users`, `created_at timestamptz`.

`sale_return_items`: `id bigint PK`, `sale_return_id bigint FK`, `product_id bigint FK`, `quantity numeric(14,3)`, `unit_price numeric(14,2)`, `tax_amount numeric(14,2)`.

### `discounts`

`id bigint PK`, `organization_id uuid FK`, `name text NOT NULL`, `type discount_type`, `value numeric(14,2)`, `applies_to_category_id bigint FK categories nullable`, `valid_till date`, `active boolean DEFAULT true`.

### `delivery_challans`, `delivery_challan_items`, `delivery_challan_returns`

`delivery_challans`: `id bigint PK`, `organization_id uuid FK`, `store_id bigint FK`, `customer_id bigint FK contacts`, `reference text`, `challan_date date`, `vehicle_number text`, `notes text`, `eway_bill_number text`, `status delivery_challan_status`, `created_by uuid FK staff_users`, `created_at timestamptz`.

`delivery_challan_items`: `id bigint PK`, `delivery_challan_id bigint FK`, `product_id bigint FK`, `quantity numeric(14,3)`, `notes text`.

`delivery_challan_returns`: `id bigint PK`, `delivery_challan_id bigint FK`, `return_date date`, `reason text`, `status return_status`.

## 8. Inventory Tables

### `inventory_balances`

`product_id bigint FK`, `store_id bigint FK`, `quantity numeric(14,3)`, `average_cost numeric(14,2)`, `updated_at timestamptz`. Composite PK: `(product_id, store_id)`.

### `inventory_movements`

`id bigint PK`, `organization_id uuid FK`, `product_id bigint FK`, `store_id bigint FK`, `movement_date date`, `movement_type inventory_movement_type`, `quantity_change numeric(14,3)`, `unit_cost numeric(14,2)`, `balance_after numeric(14,3)`, `reference_type text`, `reference_id bigint`, `reference text`, `created_by uuid FK staff_users`, `created_at timestamptz`.

Use this ledger for sales, purchases, returns, adjustments, opening stock and transfers. Suggested movement values: `IN`, `OUT`, `ADJUSTMENT`, `TRANSFER_IN`, `TRANSFER_OUT`, `OPENING`, `SALE_RETURN`, `PURCHASE_RETURN`.

### `opening_stock_entries`

`id bigint PK`, `product_id bigint FK`, `store_id bigint FK`, `quantity numeric(14,3)`, `unit_cost numeric(14,2)`, `entry_date date`, `created_by uuid FK staff_users`.

### `stock_adjustments`

`id bigint PK`, `organization_id uuid FK`, `product_id bigint FK`, `store_id bigint FK`, `reference text`, `adjustment_type adjustment_type`, `quantity numeric(14,3)`, `reason text`, `adjustment_date date`, `by_user_id uuid FK staff_users`.

### `stock_transfers` and `stock_transfer_items`

`stock_transfers`: `id bigint PK`, `organization_id uuid FK`, `reference text`, `transfer_date date`, `from_store_id bigint FK stores`, `to_store_id bigint FK stores`, `by_user_id uuid FK staff_users`, `status transfer_status`.

`stock_transfer_items`: `id bigint PK`, `stock_transfer_id bigint FK`, `product_id bigint FK`, `quantity numeric(14,3)`.

## 9. Expenses and Accounting Tables

### `expense_categories`

`id bigint PK`, `organization_id uuid FK`, `name text NOT NULL`, `created_at timestamptz`.

### `expenses`

`id bigint PK`, `organization_id uuid FK`, `reference text`, `category_id bigint FK expense_categories`, `description text`, `amount numeric(14,2)`, `expense_date date`, `paid_via payment_mode`, `bank_account_id bigint FK bank_accounts nullable`, `created_by uuid FK staff_users`, `created_at timestamptz`.

### `bank_accounts`

`id bigint PK`, `organization_id uuid FK`, `holder text`, `bank text`, `account_number text`, `ifsc text`, `type bank_account_type`, `opening_balance numeric(14,2)`, `current_balance numeric(14,2)`, `active boolean DEFAULT true`, `created_at timestamptz`.

Protect account numbers with strict RLS and application-level access controls.

### `bank_transactions`

`id bigint PK`, `bank_account_id bigint FK`, `transaction_date date`, `description text`, `transaction_type bank_transaction_type`, `amount numeric(14,2)`, `balance_after numeric(14,2)`, `payment_id bigint FK payments nullable`, `reconciled boolean DEFAULT false`.

### `ledger_accounts`

`id bigint PK`, `organization_id uuid FK`, `name text`, `account_type ledger_account_type`, `parent_id bigint FK ledger_accounts nullable`, `active boolean DEFAULT true`.

### `journal_entries` and `journal_lines`

`journal_entries`: `id bigint PK`, `organization_id uuid FK`, `entry_date date`, `reference_type text`, `reference_id bigint`, `description text`, `created_by uuid FK staff_users`, `created_at timestamptz`.

`journal_lines`: `id bigint PK`, `journal_entry_id bigint FK`, `ledger_account_id bigint FK`, `debit numeric(14,2) DEFAULT 0`, `credit numeric(14,2) DEFAULT 0`. Each entry must balance: total debit equals total credit.

### `tds_tcs_entries`

`id bigint PK`, `organization_id uuid FK`, `type tax_collection_type`, `section text`, `contact_id bigint FK contacts nullable`, `party text`, `amount numeric(14,2)`, `entry_date date`, `status tax_entry_status`, `reference_type text`, `reference_id bigint`, `created_at timestamptz`.

### `tax_filings`

GSTR-1 and GSTR-3B dashboard data should be SQL views or report queries over invoices, invoice items, purchases and tax entries, not duplicate transaction tables.

## 13. Relationships

- One organization has many stores, users, contacts, products and documents.
- A product belongs to optional category, brand, unit and manufacturer records.
- Sales orders, invoices, purchases and purchase orders have one-to-many item rows.
- Contacts act as customers or suppliers and connect to invoices, purchases, payments and returns.
- Stores and products connect through inventory balances and inventory movements.
- Payments connect invoices or purchases and can create bank transactions.
- Journal entries contain journal lines, and journal lines post to ledger accounts.
- Roles connect to users and modules through `role_module_access`.

## 14. Report Views, Not Tables

The current dashboard and report fixtures should be calculated from transaction tables. Recommended views include `v_current_stock`, `v_low_stock`, `v_sales_summary`, `v_purchase_summary`, `v_customer_balances`, `v_supplier_balances`, `v_cash_flow`, `v_balance_sheet`, `v_gstr1_summary`, `v_gstr3b_summary`, `v_fast_moving_products` and `v_slow_moving_products`.

Do not permanently store derived values such as product count, stock valuation, invoice due, total paid, days since movement, velocity or dashboard chart totals unless a later performance requirement justifies a materialized view.

## 15. Important Migration Notes

1. Existing sample records identify customers, suppliers and products by display name in some places. Replace these with foreign-key IDs.
2. Some sample purchase records do not have stable IDs. Generate IDs in PostgreSQL.
3. POS currently captures a payment mode in the UI but does not persist a payment record. Create a `payments` row when a sale is completed.
4. Tax behavior is inconsistent in the sample data. Centralize tax calculation using `tax_profiles` and line snapshots.
5. Return, transfer, staff, settings, bank and expense pages are partly sample-only. Confirm their exact fields with the business owner before production launch.
6. Use database transactions when posting an invoice or purchase so the document, payment, inventory movement and journal entries succeed or fail together.
7. Enable RLS on every organization-owned table and add indexes on every foreign key plus `(organization_id, date)` columns used by reports.
